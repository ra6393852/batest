Baccarat Live Analyzer 0.6.0 — 라이선스 등록·등록 해제·판매 설명서
================================================================

1. 먼저 확인할 사항
------------------
이 프로그램은 결과 기록과 통계 확인용입니다. 자동 베팅 기능은 없습니다.

파일 이름과 사용방법.txt 첫 줄에서 배포 유형을 확인하세요.
  Review: 판매 서버가 없는 관리자 검토용. 기존 관리자 암호로 실행합니다.
          이용 코드/PC 제한이 적용되지 않습니다. 이 파일을 보호된 판매용으로 배포하지 마세요.
  Customer: 판매자 서버 주소와 공개 검증키가 빌드에 고정된 판매용.
            유효한 이용 코드가 있어야 분석 화면과 관련 API를 사용할 수 있습니다.

현재 제공된 서버 프로그램은 직접 운영할 수 있는 패키지입니다.
서버 패키지를 다운로드했다는 이유만으로 인터넷 인증 서버가 생성되지는 않습니다.
판매 전에 서버 설치, 공개 HTTPS 주소 연결, Customer 빌드가 필요합니다.
인증 서버의 실제 배포와 결제 자동화는 이 패키지가 자동 수행하지 않습니다.

2. 구매자: 설치 없이 실행하고 코드 등록하기
----------------------------------------
1) 판매자에게 Customer ZIP과 이용 코드를 받습니다.
2) ZIP 전체를 압축 해제합니다. EXE만 따로 옮기지 마세요.
3) Baccarat Live Analyzer.exe를 실행합니다. Node.js 설치는 구매자에게 필요 없습니다.
4) [이용 코드]에 전달받은 BLA-로 시작하는 코드 전체를 넣고 [이 PC에 등록]을 누릅니다.
5) 인터넷 인증이 성공하면 분석 화면으로 들어갑니다. 판매자 관리자 암호는 필요 없습니다.
6) 오른쪽 아래 [이용권·PC 등록]에서 이용권 ID와 만료일을 확인할 수 있습니다.
7) 이후에는 동일한 Windows 계정에서 실행하면 기존 등록을 자동 확인합니다.

Chrome에서 사이트에 직접 로그인하고 바카라 방에 들어갑니다.
분석기에서 [게임 창 선택] → 해당 Chrome 창 → [자동 가져오기 시작]을 누릅니다.
게임 창을 최소화하지 말고 왼쪽 아래 숫자·색 그림판 6줄이 보이게 유지합니다.
처음 읽은 지난 기록과 이후 사전 예측 채점은 구분됩니다. 예측 성공을 보장하지 않습니다.

3. 구매자: 이 PC 등록 해제와 새 PC로 이동
---------------------------------------
1) 기존 PC에서 프로그램을 열고 [이용권·PC 등록]을 누릅니다.
2) [이 PC 등록 해제] → 확인 창에서 [이 PC 등록 해제]를 선택합니다.
3) 서버가 해제를 확인하면 분석이 중지되고 코드 등록 화면으로 돌아갑니다.
4) 기존 PC에 이미 발급된 짧은 인증이 끝날 때까지 최대 2분 기다립니다.
5) 새 PC에서 Customer 프로그램을 실행하고 같은 이용 코드를 등록합니다.
6) 남은 기간을 이어서 사용합니다. 등록 해제로 이용 기간이 다시 시작되지는 않습니다.

인터넷 연결이 없으면 서버 등록 해제를 완료할 수 없습니다. 연결을 복구하고 다시 시도하거나
판매자에게 관리자 화면의 PC 등록 해제를 요청하세요. 기존 PC가 고장 난 경우에도 같습니다.
Windows 재설치/계정 변경으로 보호 저장소를 읽지 못하면 판매자가 이전 등록을 해제해야 합니다.
등록 해제/만료/차단은 기존 SQLite 결과를 삭제하지 않습니다. 기록은 해당 PC에 남습니다.
일반적인 프로그램 종료는 동시 실행 세션만 해제하며 PC 등록은 그대로 보존합니다.

4. 이용 기간: 1개월~12개월
-------------------------
판매자가 발급할 때 1~12개월을 선택합니다. 수량은 한 번에 1~10,000개입니다.
발급한 날이 아니라 구매자가 처음 인증한 날부터 선택한 달력 개월 수를 계산합니다.
예: 한국 시간 2026-10-15 12:00에 3개월 최초 등록 → 2027-01-15 12:00 만료.
다음 달에 같은 날짜가 없으면 그 달의 마지막 날, 같은 시각으로 맞춥니다.
만료 여부는 서버 시각으로 판단합니다. PC 시간을 바꾸어도 새 인증 기간이 늘어나지 않습니다.
기간 연장은 현재 시각과 기존 만료일 중 더 늦은 시각부터 선택한 1~12개월을 더합니다.
구매자는 프로그램에서 개월 수나 만료일을 바꿀 수 없습니다.

5. 판매자: 서버 처음 준비하기
----------------------------
항상 켜져 있는 서버 1대와 공개 HTTPS 도메인이 필요합니다. 서버/도메인 비용은 별도입니다.
판매자 서버 패키지에는 server.cjs, 초기화.cmd, 서버시작.cmd와 이 설명서가 들어 있습니다.
서버에는 공식 Node.js 24를 설치합니다. server.cjs는 별도 npm 설치 없이 실행할 수 있습니다.

Windows 서버에서 간단히 시작:
  1) 판매자 서버 ZIP 전체를 별도 서버 폴더에 풉니다. 고객에게 이 폴더를 보내지 마세요.
  2) 초기화.cmd를 실행하고 공개 HTTPS 주소를 입력합니다. 예: https://license.example.com
     아직 서버/도메인이 없으면 Enter로 로컬 검토 주소를 선택할 수 있습니다.
  3) 새 판매자 관리자 암호를 12~128자로 설정합니다. 입력은 화면에 표시되지 않습니다.
  4) 서버시작.cmd를 실행해 서버를 유지합니다.
  5) HTTPS 프록시로 공개 도메인을 이 서버의 127.0.0.1:4380에 연결합니다.

터미널 명령(서버 폴더에서):
  node server.cjs init --url https://license.example.com --data license-data
  node server.cjs start --data license-data --port 4380

위 example.com 주소는 설명용입니다. 본인의 실제 주소로 바꾸어야 합니다.
처음 init은 한 번만 실행합니다. 기존 서버의 키/DB를 지우고 다시 초기화하지 마세요.
서버는 기본적으로 127.0.0.1만 수신합니다. 운영에서는 HTTPS 프록시가 필요합니다.
예를 들어 같은 서버의 Caddy에 실제 도메인을 설정합니다:
  license.example.com {
    reverse_proxy 127.0.0.1:4380
  }
DNS를 서버로 연결하고 80/443 포트, TLS 발급, 서비스 자동 재시작을 운영 환경에 맞게 설정하세요.
실제 DNS/TLS/방화벽/외부 고객 PC 접속은 배포 후 따로 검증해야 합니다.
Linux에서도 같은 node 명령을 실행하고 systemd 등으로 자동 시작할 수 있습니다.
서버 프로세스/SQLite를 하나로 운영하세요. 여러 복제 서버의 동시 운영용 DB 구조는 아닙니다.

로컬 기능 검토만 하는 경우:
  node server.cjs init --url http://127.0.0.1:4380 --data local-test-data
  node server.cjs start --data local-test-data --port 4380
  브라우저에서 http://127.0.0.1:4380/admin 접속
이 주소는 같은 컴퓨터에서만 접근합니다. 고객 판매용 빌드는 공개 HTTPS를 요구합니다.
무료 외부 연결 시험만 먼저 할 경우(고정 판매 주소가 아님):
  서버시작.cmd는 켜 둔 상태로 새 cmd 창에서 실행합니다.
  winget install --id Cloudflare.cloudflared --exact
  설치가 끝나면 cmd 창을 새로 열고 실행합니다.
  cloudflared tunnel --url http://127.0.0.1:4380
  출력된 https://...trycloudflare.com 주소가 임시 외부 주소입니다.
  서버 창과 터널 창을 둘 다 켜 두어야 합니다. 재실행하면 주소가 바뀔 수 있습니다.
  이 주소로 빌드한 파일은 Customer-Trial ZIP이며 판매 배포 전에 고정 주소를 준비해야 합니다.
  원문 관리자 암호/서버 개인 키를 전달하지 않고 공개키와 외부 주소만 빌드에 사용합니다.
  로컬 관리 화면은 계속 기존 127.0.0.1 주소로 이용할 수 있습니다.
로컬로 먼저 초기화한 뒤 실제 서버 주소를 정했다면 서버를 종료하고 다음 명령을 사용합니다:
  node server.cjs configure --url https://본인인증도메인 --data license-data
기존 키/DB를 유지하면서 서버 주소와 공개 설정을 갱신합니다. 서버를 재시작한 후 새 공개 설정으로
Customer를 빌드하세요. 로컬 테스트 코드를 실제 고객 코드와 혼동하지 마세요.

6. 판매자: 고객용 Customer 프로그램 만들기
-----------------------------------------
서버 초기화 후 license-data/license-public.json이 생성됩니다.
이 파일에는 서버 주소와 공개 검증키만 있습니다. 개발 PC로 복사합니다.
서버 개인 키가 든 server-secrets.json과 licenses.sqlite는 고객에게 전달하지 않습니다.

Node.js 24와 Git이 있는 Windows 개발 PC에서 저장소 코드를 받아 루트에서 실행:
  npm ci
  npm run setup:electron
  npm run typecheck
  npm run dist:customer -- C:/안전한폴더/license-public.json

생성: release/Baccarat-Live-Analyzer-0.6.0-x64-Customer.zip
빌드 명령은 공개 HTTPS 주소를 요구합니다. 키/주소 없이 보호된 Customer를 만들 수 없습니다.
고객에게는 Customer ZIP 전체와 해당 고객 코드만 전달합니다.
서버 주소/검증키는 빌드에 고정되며 고객이 실행 옵션/환경변수/설정파일로 바꿀 수 없습니다.
서버 주소/서명 키를 변경하면 새 Customer 빌드를 배포해야 합니다. 기존 키는 안전하게 백업하세요.
일반 npm run dist:win은 관리자 검토용 Review ZIP을 만듭니다. Customer와 혼동하지 마세요.

7. 판매자: 코드 생성·판매·기간 연장
----------------------------------
1) 브라우저에서 본인 서버의 https://실제도메인/admin에 접속합니다.
2) 초기화 때 설정한 판매자 관리자 암호로 로그인합니다. 기존 앱 공통 암호와 별개입니다.
3) [코드 발급]에서 이용 기간 1~12개월, 수량 1~10,000, 고객/배치 메모를 선택합니다.
4) [코드 생성]을 누르고 [발급 CSV 다운로드]로 저장합니다.
5) 원문 코드는 이번 발급 화면에서만 제공됩니다. CSV에는 실제 활성화 코드가 있으므로 안전하게 보관합니다.
   서버 DB에는 전체 코드 대신 해시와 끝 8자리만 저장합니다. CSV를 잃어도 고객 목록의 [코드 재발급]에서 새 코드로 교체할 수 있습니다.
6) 결제를 직접 확인한 뒤 고객에게 Customer 다운로드 주소와 코드 1개를 전달합니다.
7) 재결제 시 고객 메모/이용권 ID/코드 끝 8자리로 검색합니다.
8) [연장 기간]을 1~12개월로 선택한 뒤 해당 고객의 [기간 연장]을 누르고 확인창에서 [확인]합니다.
   처리 결과와 새 만료일은 확인창 안에 표시됩니다. 표의 최초 발급 개월 수는 바뀌지 않습니다.
9) 만료 전이면 기존 만료일부터 연장하고, 이미 만료됐으면 현재부터 연장합니다.

미사용 코드는 아직 만료일이 없어 기간 연장 대상이 아닙니다. 필요한 기간으로 새로 발급하세요.
자동 결제/이메일 발송 기능은 포함되지 않습니다. 판매자가 결제 확인 후 발급·연장합니다.

8. 판매자: PC 등록 해제·차단·변경 이력
-------------------------------------
고객 관리 표에서 원하는 고객을 찾고 다음 버튼을 사용합니다.
  [PC 등록 해제]: 기존 PC 연결을 해제합니다. 새 PC는 최대 2분 후 같은 코드로 등록합니다.
  [사용 차단]: 환불/유출 등으로 이용권 사용을 중지합니다.
  [차단 해제]: 차단 상태만 해제합니다. 기존 만료일은 그대로입니다.
  [코드 재발급]: 새 코드로 교체하며 이전 코드를 무효화합니다. 남은 기간·PC·정상 실행 인증·차단 상태를 보존합니다.
    확인창에서 [새 코드 발급] 후 [새 코드 복사]를 눌러 전체 코드만 전달합니다. 여러 번 재발급하면 마지막 코드만 유효합니다.
    새 코드가 필요해도 별도 이용권을 새로 만들 필요가 없습니다. 기간 연장/PC 이동은 별도 관리 버튼을 사용합니다.
  [변경 이력]: 최초 등록, PC 등록/해제, 기간 연장, 차단, 코드 재발급 기록을 확인합니다.
표는 100개 단위로 조회하며 다음/이전 버튼과 검색을 사용합니다.
관리 버튼은 페이지 안의 확인창을 사용합니다. 취소하면 변경하지 않으며 오류도 같은 창에 표시합니다.
화면 아래 [관리자 암호 변경]에서 현재 암호와 새 암호를 입력해 바꿀 수 있습니다.
변경하면 모든 관리자 세션이 종료됩니다. 관리자 로그인 세션은 1시간입니다.
서버 키나 코드 CSV를 채팅/고객 안내/공개 저장소에 올리지 마세요.

9. 복사·USB·동시 실행·오프라인 처리
---------------------------------
파일은 이메일/USB로 복사할 수 있지만, 판매용 Customer는 코드당 등록 PC 1대를 확인합니다.
PC 인증 개인 키는 EXE/USB 폴더 밖 Windows 사용자 프로필에서 DPAPI로 보호합니다.
프로그램 폴더와 코드만 다른 PC로 복사해도 새 PC 인증은 거절됩니다.
TPM 하드웨어 키는 이번 버전에 구현하지 않았습니다. DPAPI는 Windows 계정에 의존합니다.
인터넷으로 시작 시 및 사용 중 약 30초마다 갱신하고 짧은 인증은 최대 2분입니다.
인증 실패/차단/만료를 확인하면 자동 캡처와 분석 접근을 중지하고 기록은 유지합니다.
관리자 해제/차단이 기존 실행에 반영되기까지 통신 상태에 따라 최대 2분 걸릴 수 있습니다.
등록 해제/차단 후 새 등록에도 이전 인증 종료까지 최대 2분 대기할 수 있습니다.
비정상 종료 후 [이미 실행 중]이면 기존 실행을 종료하고 최대 2분 후 다시 시도합니다.
오프라인 사용 유예는 없으며 서버 장애 시 새 인증/분석을 진행할 수 없습니다.
서버에는 라이선스·기기·기간만 전달하며 게임 이미지/사이트 암호/쿠키는 보내지 않습니다.
전문적인 앱 변조/크랙, Windows 계정 전체 탈취까지 완전히 막는 기능은 아닙니다.
기존에 배포된 보호 없는 구버전의 사용을 이 서버가 소급해서 막지는 못합니다.

10. 서버 백업과 검사
--------------------
고객에게 배포하기 전에 별도 Windows PC 2대로 등록/복사본 거절/해제/이동/만료를 확인하세요.
서버를 안전하게 종료하고 license-data 폴더 전체를 암호화된 백업으로 보관합니다.
server-secrets.json(서명 키/관리자 검증값), licenses.sqlite, license-public.json을 함께 보존합니다.
실행 중 SQLite 파일 하나만 단순 복사하면 WAL 기록이 누락될 수 있습니다.
운영자는 서버 정상 여부(/health), HTTPS 만료, 서비스 자동 재시작, 백업 복원을 확인해야 합니다.
서버 시계를 동기화하고 백업 접근 권한을 판매자에게만 제한하세요.
코드 수천 개 발급은 지원하지만 동시 접속 수천 명 운영 성능은 별도 부하 검증이 필요합니다.

개발 검사:
  npm test
  npm run license:build && npx --no-install playwright test --config playwright.server.config.ts
  bash scripts/test-cloud.sh           (Linux 단위/기존 Electron)
  npm run test:licensed                (Windows 실제 인증 서버 + 판매용 소스 앱)
  npm run test:licensed -- --package    (Windows 실제 판매용 EXE까지)
검사는 임시 서버/임시 코드/임시 사용자 데이터로 수행하며 실제 고객 데이터는 사용하지 않습니다.

문제별 대처:
  [다른 PC에 등록됨] → 기존 PC에서 해제하거나 판매자에게 PC 등록 해제를 요청.
  [최대 2분 후 다시 등록] → 기존 짧은 인증 종료 후 재시도.
  [이미 실행 중] → 이전 프로그램을 완전히 종료하고 최대 2분 대기.
  [이용 기간 만료] → 결제 확인 후 판매자가 기간 연장, 구매자는 기존 등록 다시 확인.
  [서버 연결 실패] → 인터넷/HTTPS/서버 실행/도메인/고객 빌드의 공개 키 일치 여부 확인.
  [보호 저장소 실패] → 원래 Windows 계정 사용, 판매자 등록 해제 후 새 등록.
  [Review 파일] → 인증 서버 연결 후 dist:customer로 만든 Customer 파일을 사용.


서버 파일만 업데이트할 때
-------------------------
기존 서버를 종료하고 license-data 전체를 백업한 뒤 server.cjs만 기존 폴더에 덮어씁니다.
license-data와 서명 키는 보존하고 초기화.cmd를 실행하지 않습니다. 서버시작.cmd로 다시 실행한 뒤
관리 페이지를 Ctrl+F5로 새로고침합니다. 고객 앱과 Cloudflare 터널은 다시 설치할 필요가 없습니다.
자세한 순서는 서버 업데이트 ZIP의 업데이트방법.txt를 참고하세요.
