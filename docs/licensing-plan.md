# 월 단위 판매 라이선스 설계안

이 문서는 추천 설계이며, 현재 앱에 인증 서버나 판매 코드 기능을 구현한 상태는 아닙니다. 현재의 공통 시작 암호를 알면 복사본에도 입력할 수 있으므로 판매용에는 구매자별 라이선스가 필요합니다.

## 추천 상품과 이용 흐름

- 기본 상품: 최초 활성화부터 30일, 등록 PC 1대, 동시 실행 1개.
- 프로그램 파일은 무설치 ZIP으로 배포하고, 첫 실행 때 구매자 코드를 서버에서 활성화합니다.
- 갱신은 같은 고객 라이선스의 만료일을 `max(현재 시각, 기존 만료일) + 30일`로 연장합니다. 매월 앱을 새로 배포할 필요가 없습니다.
- 관리자가 결제를 확인하고 발급/연장하는 방식으로 먼저 운영할 수 있습니다. 자동 결제는 별도 단계입니다.
- PC 교체는 관리자 승인으로 이전 등록과 세션을 폐기한 뒤 새 기기를 등록합니다. 초기화 횟수와 변경 기록을 관리합니다.
- 만료·회수 때 새 분석/수집을 제한하며 기존 기록은 삭제하지 않습니다.

## 수천 개 코드의 발급과 관리

앱 안에 유효 코드 목록을 넣지 않습니다. 서버가 암호학적으로 안전한 무작위 128비트 이상 코드를 만들고, DB의 고유 제약과 트랜잭션으로 중복 발급과 동시 활성화를 막습니다. 순번이나 날짜를 조합한 예측 가능한 코드는 사용하지 않습니다.

관리자는 1,000개/10,000개 단위로 발급 배치를 만들고 CSV로 내려받을 수 있게 합니다. 원문 코드는 발급 때만 전달하고 DB에는 코드 해시를 저장합니다. 원문 CSV는 구매 활성화 권한이 있는 자료이므로 관리자만 접근합니다. 분실한 미사용 코드는 폐기하고 다시 발급합니다.

각 코드에는 라이선스 ID, 발급 배치, 상품/이용 기간, 미사용·사용 중·만료·차단 상태, 최초 등록일, 서버 기준 만료일, 등록 기기, 최근 인증 시각을 연결합니다. 구매자별 검색, 일괄 연장/차단, PC 등록 초기화와 변경 이력을 제공하는 관리자 화면을 둡니다.

수천~수만 건의 코드 목록은 일반 관계형 DB로 충분합니다. 실제 서버 부하는 코드 개수보다 동시 실행 수와 인증 주기가 좌우합니다. 예를 들어 1,000명이 하루 종일 60초마다 인증하면 하루 약 144만 건, 30일 약 4,320만 건의 갱신 요청이 발생합니다. 운영비는 서버·DB·백업·접속 규모에 따라 따로 산정합니다.

## USB/폴더 복사에 대한 제한

기기 등록 때 PC별 키 쌍을 생성합니다. 개인 키는 USB나 앱 폴더에 두지 않고 Windows 사용자 프로필의 DPAPI 보호 저장소에 둡니다. 가능하면 TPM의 내보낼 수 없는 키를 사용합니다. 서버에는 공개 키와 최소한의 등록 식별값만 저장합니다.

활성화와 주기 인증은 새 요청에 대한 기기 키의 서명을 확인합니다. 다른 PC로 앱과 라이선스 파일을 복사해도 등록 기기의 키를 사용할 수 없으므로 인증을 거절합니다. 사용자 이름·IP 주소만으로 PC를 구분하지 않습니다. Windows 재설치나 기기 변경은 등록 초기화 절차로 처리합니다.

서버는 라이선스 1개당 활성 기기 1개와 세션 1개만 허용하고 짧은 유효 기간의 사용 권한을 발급합니다. 기기와 라이선스에 연결된 권한을 서버 키로 서명하며 앱에는 검증용 공개 키만 넣습니다. 서명용 개인 키와 관리자 권한은 서버에 둡니다.

서버 시각으로 만료를 판정하고, 실행 시 및 사용 중 정기적으로 갱신합니다. 동시 실행 제한이 중요하므로 최초 판매 버전은 온라인 인증을 기본으로 권합니다. 오프라인 유예를 추가하면 그 시간 동안 회수·동시 사용 통제가 늦어지므로 별도 운영 정책으로 정합니다. 네트워크 실패 시에는 상태를 설명하고 기존 기록을 유지합니다.

## 관리자와 서버 구성

Electron 앱은 인증 API를 사용하고, 별도 HTTPS 인증 서버와 관계형 DB가 코드·기기·기간·세션을 관리합니다. 관리자 웹 화면은 고객 앱의 공통 암호와 분리된 관리자 로그인으로 보호합니다. 발급/연장/차단/기기 초기화 요청은 서버에서 관리자 권한을 검증하고 기록합니다.

처음에는 결제 확인 → 코드 발급 → PC 활성화 → 30일 사용 → 결제 확인 후 연장 순서가 적합합니다. 인증 서버를 배포하고 비용을 발생시키는 작업은 별도로 진행해야 합니다. 게임 이미지·사이트 로그인 비밀번호·쿠키를 인증 서버로 보낼 필요는 없습니다.

## 보호 범위

이 구조는 일반적인 코드 공유와 USB/폴더 복사를 제한합니다. 사용자가 소유한 PC에서 실행하는 앱의 분석 코드까지 복제를 완전히 막는다고 보장할 수는 없습니다. 코드 서명과 난독화는 보조 수단이며, 만료·기기 등록·세션 결정은 서버에서 관리합니다.
