# 구조와 실제 사이트 연결 조건

## 현재 기본 입력: 게임 창 그림판 이미지

0.5.2의 일반 실행은 사이트 DOM/방 이름/회차 텍스트를 사용하지 않습니다. `window-capture.ts`가 선택한 외부 창의 왼쪽42%/아래45%를 1초마다 가져오고, `double-bitmap.ts`가 픽셀을 2배로 복제합니다. `bead-image.ts`의 6행 격자/색 판독과 선택적 `score-reader.ts`의 숫자 OCR을 사용합니다. 이미지는 저장/전송하지 않습니다.

`visible-board-session.ts`는 기존 `LiveSession`의 두 번 확인·사전 채점 로직을 재사용하며 그림판마다 독립된 분석 그룹을 부여합니다. 번호는 보이는 첫 결과부터의 상대 순서입니다. 기존 결과 순서가 달라지거나 줄어든 화면을 두 번 확인하면 새 그룹으로 전환하고 옛 기록은 보존합니다. 같은 결과 순서인 다른 방을 자동 식별할 수 없으며 사용자가 새 그림판 기록으로 분리합니다. 처음 읽은 이력은 과거 기준 자료로 저장하고 연속 관측한 새 결과만 첫 관측 전에 저장된 예측으로 채점합니다.

0.5.3의 색 검사에서는 원 안의 작은 반대색 연결 성분이 크기/위치/본체 색 지지 조건에 맞는 쌍 표시일 때만 제외합니다. 흰 숫자는 색 표본에서 제외하며 본체 색이 실제로 섞인 경우에는 기존92% 일치 기준으로 보류합니다. 화면 판독이 보류되면 원 번호와 일치 값을 표시합니다.

`background-scores.ts`는 승패 확인과 독립적인 숫자 작업을 실행하며 처리 중인1개/최신 대기1개만 유지합니다. 확인된 승패를 먼저 저장하고 예측/채점한 뒤, 숫자 OCR이 완료되면 기존 결과에 점수만 추가합니다. 기존 예측이나 O/X를 다시 생성하지 않습니다. 자동 수집 숫자는 개별 반복 재시도를 하지 않으며 이미 읽은 점수는 다시 OCR하지 않습니다. 중지/그룹 변경 시 늦게 끝난 점수 작업은 무시합니다. D의 점수 조건은 해당 예측 저장 시점에 이미 알려진 점수만 사용합니다.

미리보기는 인식한 그림판만 원본100%/2배200% PNG로 표시합니다. 확대 이미지 드래그는 로컬 미리보기의 스크롤만 변경하며, 프로그램 제목 드래그는 검증된 로컬 IPC를 통해 분석기 창 위치만 변경합니다.

## 모듈

```text
src/collector/dom.ts       순수 DOM 판독 + 신규/기존 기록 구분
src/collector/ocr.ts       B/P/T 단일 텍스트 OCR 해석
src/preload/collector.ts   격리된 읽기 전용 수집 실행
src/shared/validation.ts   수집 데이터/프로필 검증
src/analysis/engine.ts     A/B/C/D 모델과 통계·확률 오차
src/main/store.ts          SQLite 저장, 불변 예측, 확정·채점
src/main/index.ts          Electron 브라우저·IPC·로컬 OCR·CSV
src/preload/dashboard.ts   로컬 UI 전용 제한 API
src/renderer              한국어 통계 UI
```

수집기는 `Observation[]`만 전달합니다. Chrome MV3 확장의 격리된 content script에서 동일한 DOM 판독을 재사용합니다. 확장 service worker가 `127.0.0.1:38741` WebSocket에 연결하고 1회 코드로 연결한 뒤 로컬 인증 토큰으로 자동 재연결합니다. 서버는 extension Origin·Host·메시지 크기/빈도·프로필 출처를 검증합니다. 로그인 정보, 쿠키, 전체 URL, 원본 DOM을 전송하거나 로그에 남기지 않습니다. 실제 에볼루션 프로필과 Chrome 색상 그림장/OCR은 아직 미검증·미구현입니다. 원격 페이지에는 대시보드 API나 Node API를 노출하지 않습니다.

아래 사이트 어댑터/Chrome 확장 설명은 내부 개발용 경로입니다. 일반 무설치 배포는 프로토콜을 등록하지 않으며 Chrome 연결 서버를 시작하지 않습니다. 확장 경로가 필요할 때만 `--enable-chrome-bridge`로 실행합니다. 동일 인스턴스가 이미 열려 있으면 분석기 창을 앞으로 가져옵니다.

## 사이트 어댑터

현재 `box-1515.com`의 로그인 이후 화면, 제공자 이름, DOM/iframe 구조, 내장 브라우저 허용 여부는 확인되지 않았습니다. 실제 사이트용 선택자를 추측하거나 사설 API를 역분석하지 않았습니다. 기본 상태에서 사이트의 자동 수집은 꺼져 있습니다.

사이트/제공자가 허용한 구조를 확인한 뒤 `docs/adapter.example.json` 형식의 프로필을 만들고 앱에서 가져옵니다. 예제는 실제 사이트용 프로필이 아닙니다. 단순히 hostname을 바꿔도 작동이 보장되지 않습니다. 프로필에는 스크립트, 비밀번호, 쿠키, 토큰을 넣을 수 없습니다.

필수로 확인할 정보:

- 안정적인 방 ID와 화면에 표시된 방 이름.
- 새 슈마다 바뀌는 **명시적인 슈 ID**. 회차 감소만으로 임의 슈를 만들지 않음.
- 확정된 결과마다 명시적인 회차 번호와 B/P/T 값.
- 결과 행 선택자가 **확정 결과만** 포함하는지. 현재 진행 중인 게임이나 베팅 선택 제외.
- 결과 발생 시각 속성이 있다면 UTC ISO 8601 `Z` 형식. 없으면 관측 시각을 별도로 표시.
- 해당 출처의 iframe, 팝업, 로그인 리디렉션 및 내장 브라우저 정책.

Chrome 확장은 사용자가 해당 도메인의 읽기를 허용한 프레임에서만 실행하며, 프로필의 출처와 일치하는 프레임의 명시적 결과만 판독합니다. 교차 출처 iframe은 해당 제공자 도메인을 따로 허용해야 합니다. 닫힌 shadow DOM, 제공자 영상/캔버스의 색상 그림장에 대한 동작은 검증되지 않았습니다. 전체 이력은 현재 화면이 제공하는 범위 밖에서 복원하지 않습니다. 확정 결과가 500개보다 많으면 마지막 500개만 읽습니다.

`confidence`는 어댑터가 검증을 통해 부여하는 인식 신뢰도이며 다음 판의 확률이 아닙니다. 0.92 미만은 확인 대기입니다. 임의로 1로 바꾸면 실제 인식이 정확해지는 것이 아닙니다. 틀린 높은 신뢰도 결과도 서로 충돌하면 덮어쓰지 않습니다.

선택적인 `ocr` 설정은 `imageSelector`, `roundSelector`, `roundAttribute`로 자동 식별한 **확정 결과 텍스트** 영역만 캡처합니다. OCR은 로컬 Tesseract 영어 모델로 B/P/T 또는 BANKER/PLAYER/TIE 단일 텍스트만 해석합니다. 화면 전체를 저장하거나 외부 OCR 서비스로 전송하지 않습니다. 색상 원과 선으로 구성된 그림장을 판독하는 OpenCV 어댑터는 아직 없습니다. 수동 영역 선택으로 이 한계를 숨기지 않습니다.

## 기록과 예측

- `(room_id, shoe_id, round)`가 결과의 유일 키입니다. 충돌은 확인 대기로 남깁니다.
- 예측은 `cutoff_round`, `target_round`, `horizon`, `created_at`, 모델 분포, 표본 수를 불변 행으로 저장합니다. 채점은 별도 테이블입니다. 결과와 예측, 채점의 UPDATE/DELETE는 DB 트리거가 차단합니다.
- 한 스냅샷 전체를 저장한 후 최대 확정 회차 뒤의 미관측 목표만 예측합니다. 이미 본 확인 대기 결과에 대해 새 사전 예측을 만들지 않습니다.
- 첫 판독의 기존 이력은 채점하지 않습니다. 이후 실제 결과 시각이 제공되면 예측 생성 시각보다 엄격히 늦어야 채점합니다. 시각이 없으면 최초 관측 시각으로 비교하므로 **관측 전에 저장**된 것만 보장할 수 있습니다. 실제 발생 전 저장의 완전한 검증은 신뢰할 수 있는 제공자 시각이 필요합니다.
- 늦게 확인한 저신뢰 결과는 확인 시각이 아니라 최초 관측 시각을 기준으로 채점합니다.
- horizon 1~4는 해당 거리의 관측된 과거 사례를 사용하며, 가상 예측을 실제 학습 기록에 추가하지 않습니다. 같은 목표 회차에 대한 서로 다른 기준/거리의 기록을 모두 유지합니다.
- 회차 누락과 슈 경계에서는 연속/전환/패턴을 연결하지 않습니다. B는 현재 연속 관측 구간의 최근 20회, C/D는 해당 방에서 확인된 구간들의 과거 패턴을 사용합니다.
- 타이는 B/P 연속을 끊지 않습니다. 일반 O/X에는 타이를 포함합니다. 타이 제외 적중률은 실제 결과 T인 회차를 제외합니다.
- 방식 간 비교는 A/B/C/D가 모두 채점된 동일 목표 회차의 horizon 1만 사용합니다. 최근 10/30/100은 이 공통 채점 회차의 마지막 N개입니다.

## 영속성과 보안

SQLite는 `sql.js` WASM 엔진을 사용하고 트랜잭션마다 로컬 SQLite 파일을 임시 파일 + fsync + 원자 교체로 저장합니다. 저장 실패 시 메모리 DB도 이전 상태로 복구합니다. 네이티브 Node ABI 재빌드 없이 Windows에서 동일 엔진을 사용할 수 있습니다. 대규모 기록에서는 전체 DB 직렬화 비용이 있으므로 장기 운영 시 디스크 기반 네이티브 SQLite로 교체를 검토해야 합니다.

Electron `userData`의 `baccarat.sqlite`에 분석 기록을, Electron 영속 세션에 사이트 로그인 상태를 보관합니다. 앱은 로그인 입력값을 읽거나 별도로 수집하지 않습니다. 브라우저 자체의 정상적인 세션 저장은 이루어집니다. 원격 페이지를 기록하는 파일 로그는 생성하지 않습니다. 외부 이동은 HTTPS와 명시적인 허용 호스트만 허용하며 TLS 검증, webSecurity, sandbox, contextIsolation을 켭니다. 카메라/마이크 등 권한은 거절합니다.

자동 클릭, 베팅 입력, 베팅 전송, 키 입력 시뮬레이션, 인증 우회, 결과 조작 API는 제공하지 않습니다.
