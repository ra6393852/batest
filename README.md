# Baccarat Live Analyzer

Windows 10/11용 읽기 전용 바카라 통계 프로그램입니다. `ra6393852/batest`에서 Electron/React/TypeScript와 SQLite로 개발합니다. **0.5.7은 시작 관리자 암호, 1회차부터의 과거 검증, 반복 통계·이미지 전달 최적화를 추가합니다.** 숫자 그림장은 색으로 승패, 숫자로 표시 점수를 읽습니다.

## 한눈에 보는 실시간 화면

왼쪽은 게임 창 선택·수집 상태·그림판, 오른쪽 위는 A/B/C/D 누적 적중률과 예상 답/O/X입니다. 그림판은 기본 **한눈에 보기**로 전체가 들어오게 표시합니다. 100%·200% 확대 및 드래그도 유지하며 실제 판독은 항상 2배 픽셀로 진행합니다. 화면 전체를 스크롤하면 왼쪽 모니터가 유지됩니다. 별도의 좌우 패널 세로 스크롤은 없습니다.

기본 **1회차부터 보기**는 저장된 첫 회차부터 현재까지의 실제 결과와 A/B/C/D 답·O/X, 그리고 다음 4회차를 같은 표에서 번호순으로 표시합니다. 실제 결과 전에 저장한 답이 있으면 **사전 예측**으로, 없으면 해당 판 이전의 결과와 점수만 사용해 다시 계산한 **과거 검증**으로 표시합니다. 첫 회차는 앞선 기록이 없어 8덱 이론값을 사용합니다. 회차가 빠진 구간에서는 학습을 새로 시작하며 누락 결과를 만들지 않습니다.

**과거 검증률**과 **사전 예측 적중률**은 별도입니다. 과거 검증은 현재 모델과 현재 확인한 점수로 재계산하며 실제 사전 기록이라고 주장하지 않습니다. 실시간 보기에서는 최근 사전 채점과 다음 4회차에 집중합니다. 예전 기준 회차를 선택하면 당시 고정 저장한 4개 예측을 확인합니다.

자동 수집 사용 안내와 예측·채점 기준은 접어서 공간을 확보합니다. 판독 보류 사유는 수집 상태에 표시하고, 대기 중의 적중률은 저장된 기록 기준임을 명시합니다. 현재 그림판이 확인되기 전에는 이전 그림판의 예상 답을 표시하지 않습니다.

## 시작 관리자 암호

매번 실행할 때 요청하신 관리자 암호로 잠금을 해제합니다. 잠금 상태에서는 기록 조회·그림판 입력·캡처·내장 브라우저·CSV 기능의 IPC 호출도 거절합니다. 암호는 저장소에 평문으로 넣지 않고 salt와 scrypt 검증값만 포함합니다. 여러 번 틀리면 잠시 재시도를 제한합니다. 이 잠금은 프로그램 접근용이며 SQLite 파일 암호화나 Windows 권한 승격 기능은 아닙니다.

테스트는 임시 `baccarat-` 폴더의 별도 프로필과 무작위 fixture 암호를 사용합니다. `DESKTOP_TEST_PASSWORD`는 격리된 `--smoke-test` 프로필에서만 적용하고 일반 실행에서는 무시합니다. 실제 관리자 암호는 테스트 코드·로그·CI 설정에 넣지 않습니다.

통계 스냅샷은 변경 전까지 재사용하며, 결과·점수·확인 대기가 바뀌면 캐시를 비웁니다. 외부 호출자가 반환값을 수정해도 저장 기록이나 캐시에 반영되지 않습니다. 같은 미리보기 PNG는 최초와 변경 시에만 IPC로 전달하고 매 관측의 상태·시각은 계속 전달합니다. 프런트엔드의 과거 검증과 회차 인덱스도 데이터가 바뀔 때만 계산합니다.

승자 점수만으로 남은 카드 구성을 알 수 없습니다. 확률 분석을 보강하려면 같은 방·같은 슈의 시작부터 플레이어/뱅커 양쪽의 실제 카드 숫자와 장수가 필요합니다. 그림판 기반 추정의 예측 우위는 아직 입증되지 않았습니다.

## 무설치 실행과 자동 이미지 가져오기

1. 기존 프로그램을 닫고 무설치 ZIP **전체**를 폴더에 풉니다.
2. **Baccarat Live Analyzer.exe**를 실행하고 관리자 암호로 잠금을 해제합니다. EXE와 `resources` 등 모든 파일을 함께 유지하세요. Node.js 설치는 필요 없습니다.
3. 평소 사용하는 **Chrome에서 직접 로그인하고 바카라 게임 창을 엽니다.**
4. 프로그램의 **게임 창 선택**을 누르고 Chrome의 실제 게임 창을 선택한 뒤 **자동 가져오기 시작**을 누릅니다. 확장 프로그램 설치는 필요 없습니다.
5. 왼쪽 아래 화면을 **1초 간격**으로 가져와 **2배 확대하여 판독**합니다. 6행 비드로드를 두 번 확인한 뒤 바로 B/P/T를 저장하고 예측·O/X를 갱신합니다. **숫자 OCR 완료를 기다리지 않습니다.** 숫자는 별도 작업에서 확실한 값만 추가하며 기존 예측과 채점을 수정하지 않습니다. 인식한 그림판 부분만 미리보기에 표시합니다.

미리보기의 **승패 판독 ○ms**는 해당 화면의 캡처·승패 판독·저장 처리 시간이며 두 번 확인하는 대기 시간은 별도입니다. 숫자 OCR은 자동 수집에서 개별 숫자 반복 재시도를 하지 않습니다. 진짜 색 충돌/가림이 남으면 **몇 번째 원의 색상 일치가 낮은지** 보류 사유에 표시합니다. 92% 기준 자체를 낮추거나 불확실한 결과를 강제 확정하지 않습니다.

게임 창을 최소화하지 말고 **왼쪽 아래 채워진 색 원 비드로드 6행**이 보이도록 열어 두세요. 방 이름이나 전체 결과 수(# 숫자)는 필요 없습니다. 현재 캡처 위치는 제공된 Evolution 배치 기준으로 창 왼쪽 42%, 아래 45%입니다. 다른 배치·가려진/최소화된/검은 화면은 보류 사유를 표시합니다. 실제 Evolution 로그인 화면의 자동 판독 성공은 아직 검증하지 않았습니다.

**한눈에 보기 / 원본 100% / 2배 200%**로 미리보기를 전환하고, 확대 이미지가 화면보다 넓으면 이미지를 잡고 드래그해 이동하세요. 프로그램 맨 위의 **Baccarat Live Analyzer 제목 부분**을 잡고 드래그하면 프로그램 창을 이동합니다. 2배 확대는 원본 픽셀을 그대로 복제하며 보이지 않는 정보를 새로 만들어 내지 않습니다.

기록은 **그림판 1, 그림판 2…**로 분리합니다. 기존 순서와 달라지거나 개수가 줄어든 그림판을 두 번 확인하면 새 기록으로 전환하고 이전 기록을 보존합니다. 빈 그림판도 새 기록으로 구분합니다. **방 이름을 확인하지 않으므로 서로 다른 방의 그림판 순서가 완전히 같으면 구분할 수 없습니다.** 이때는 **새 그림판 기록**을 누르세요. 새 Chrome 창이 열리면 그 창을 다시 선택합니다.

번호는 **현재 보이는 첫 결과를 1번으로 센 상대 기록 번호**입니다. 사이트 실제 회차 번호나 슈 시작부터의 전체 기록이라고 보장하지 않습니다. 보이지 않는 과거 기록을 채우지 않습니다.

**게임 창 이미지 자동 가져오기** 제목 옆의 **실행 버전 0.5.5**를 확인하세요. 실제 실행 중인 앱에서 읽은 번호입니다. 다른 분석기가 실행 중이면 새 EXE를 시작하지 못하므로 기존 프로그램을 닫고 다시 실행하라는 알림을 표시합니다. 새 파일을 열었는데 옛 창만 나타나는 상황을 숨기지 않습니다.

판독 대기에는 **현재 화면 ○개 원 후보 · 확정 대기**와 **예측 기준 갱신 대기**를 표시하며 이전 회차의 제목/선택을 현재 예측으로 표시하지 않습니다. 두 번 확인·저장을 마치고 같은 그림판 기록이 대시보드에 로드된 뒤 기준 번호를 갱신합니다. 보이는 결과33개가 확인되면 **33회차 기준 → 34~37회차**, 다음34개 확인 후에는 **34회차 기준 → 35~38회차**입니다.

## 숫자 그림판과 실시간 모니터

**초록 원의 숫자8은 T(타이)와 표시점수8로 따로 기록**합니다. 진단 문구의B/P/T는 결과 분류이며 원 안에 알파벳이 있어야 한다는 뜻이 아닙니다. 숫자 인식은 별도 OCR이며 확실하지 않은 점수는 비웁니다.

승패 색은 색상각/채도로 구분해 청록빛 초록 음영이 파랑 표에 섞이지 않도록 합니다. 실제로 본체 색이 섞인 원과 흰 숫자/회색 픽셀은 강제 확정하지 않으며92% 색상 일치 기준을 유지합니다.

**실시간 그림판 모니터는 확인 중·수집 중·새 그림판 기록 중에도 계속 표시**됩니다. 화면 가져오기/판독이 일시적으로 실패하면 마지막 유효 이미지를 유지하고 상태와 촬영 시각을 표시합니다. 다른 게임 창을 선택하면 이전 창의 이미지를 현재 화면으로 재사용하지 않습니다.

판독은 별도 Node 스레드에서 수행합니다. 처음 그림판 위치를 찾은 후에는 여백을 포함한 그림판 영역만 읽고, 픽셀이 같으면 분석/PNG 생성을 반복하지 않습니다. 캡처는 계속1초마다 실행하며 두 번 확인과 관측 시각 검증은 유지합니다. 위치/창 크기가 바뀌거나 영역 검증에 실패하면 전체 캡처에서 다시 찾습니다. **승패 판독ms는 분석 작업 시간, 캡처 포함ms는 해당 프레임의 전체 처리 시간**입니다. 모든 PC에서 같은 시간을 보장하지 않습니다.

## 클립보드 입력과 숫자 점수

자동 가져오기를 중지한 상태에서 **Ctrl+V** 또는 **클립보드 이미지 붙여넣기**도 사용할 수 있습니다. 새 캡처가 필요할 때만 Win+Shift+S를 사용합니다. 원본 100% / 확대 150%로 B/P/T 순서·숫자 점수·방·슈·시작 번호를 확인하고 저장하세요.

비드로드는 6행 위→아래, 왼쪽 열부터 읽습니다. 빨강 B·파랑 P·초록 T는 각각 한 회차입니다. 흰 숫자는 그림판에 표시된 **0~9 점수**이며 양쪽 카드 정보가 아닙니다. 읽지 못한 점수는 비워 두고 수정할 수 있습니다. 자동 수집에서는 숫자 OCR 신뢰도 92% 이상만 저장합니다. 점수가 미확인이어도 확실한 승패는 기록할 수 있습니다. 확인된 점수는 덮어쓰지 않습니다.

클립보드 빅로드는 B/P 연속과 꺾임으로 읽고 초록 타이 표시당 1회를 기본으로 펼칩니다. 여러 타이가 겹친 경우 사용자가 횟수를 확인해야 하므로 빅로드는 자동 수집 대상이 아닙니다. 클립보드 판독은 결과 7개 이상, 자동 수집은 완전한 격자로 검증한 비드로드 1개 이상을 지원합니다.

원 위치·격자·색 분석과 점수 OCR은 로컬에서 수행합니다. 이미지·파일 경로·로그인 정보는 DB/로그에 저장하지 않습니다. 기록은 기존 Windows 사용자별 앱 데이터 위치의 SQLite에 유지하며 0.4.x 기록을 자동 이관합니다.

## 네 방식의 예측·채점

| 방식 | 근거 |
| --- | --- |
| A | 표준 8덱 이론값: B 45.86%, P 44.62%, T 9.52% |
| B | 최근 최대 20회 출현 비율 + 이론값 평활 |
| C | 같은 B/P 연속 상태의 과거 1~4회차 뒤 결과 |
| D | 해당 방의 과거 2개 결과 패턴, 또는 동일 승패·점수의 사례가 3개 이상이면 점수 조건 통계 |

A는 이론값의 최댓값인 B를 항상 선택합니다. B/C/D도 표본이 없으면 이론값을 사용하며 표본 수와 대체 여부를 화면에 표시합니다. 충분한 플레이어/타이 관측이 있으면 최대 추정값에 따라 P/T를 선택할 수 있습니다. 시작 시 채점 표본이 0건이면 퍼센트 대신 **채점 대기**를 표시합니다.

22회차까지 확인하면 **23~26회차 각각 A/B/C/D가 하나의 B/P/T 답을 선택해 저장**합니다. 최댓값의 답을 표시하며 확률 분포는 펼쳐서 확인합니다. 23회차 결과를 읽으면 먼저 저장된 답을 O/X로 채점한 뒤 24~27회차 예측을 새로 저장합니다. 이전 22회차 기준 예측은 수정하지 않고 기준 회차 선택으로 다시 볼 수 있습니다. 26회차 완료 후에는 27~30회차를 생성합니다.

자동 최신 보기에서는 **최근 완료 회차의 O/X를 미래 4회차 바로 위**에 표시합니다. 결과를 이미 기록했어도 초기/복원/예측 이전 관측에 해당하면 해당 예측은 **제외**로 표시합니다. 불확실한 결과는 두 번 확인할 때까지 저장하지 않습니다. 그림판 내용 변경·수집 중지 시에는 기존 예측으로 새 기록을 사후 채점하지 않습니다.

**방식 아래의 퍼센트는 관측된 적중률 O / (O+X)**입니다. 대기는 분모에서 제외합니다. 모든 결과 T도 O/X로 채점하며 타이 제외 비율은 실제 T 회차만 제외합니다. 비교는 방·슈·기준·목표 회차가 같은 A/B/C/D 공통 예측만 사용합니다. 4회차 누적은 서로 다른 기준에서 같은 목표를 예측한 건도 각각 세고, 즉시 다음 회차 성과도 별도로 제공합니다.

첫 화면의 과거 이력은 사후 채점하지 않습니다. 연속 수집 중 새 결과만 이미지의 **첫 관측 시각 이전**에 저장된 예측에 채점합니다. 방 이동·수집 중단·재시작 중 놓친 기록은 기준 자료로 복원하며 맞췄다고 소급 집계하지 않습니다. 실제 게임 결과 발생 시각은 화면에서 확인하지 못하므로 기록은 관측 순서 검증입니다.

B/C/D는 과거 통계의 추정이며 예측된 결과를 다시 학습에 넣지 않습니다. 누락·슈·방 경계를 가로질러 패턴을 연결하지 않습니다. 남은 카드 구성을 알 수 없으므로 실제 다음 판의 정확한 확률이나 예측 우위가 입증된 값이 아닙니다.

## 개발·Windows ZIP 빌드

Node.js 24와 Git을 준비한 뒤 저장소 루트에서:

```powershell
npm ci
npm run setup:electron
npm run build
npm start
```

Electron 실행 파일은 `setup:electron`로 공식 체크섬/TLS 검증을 유지해 내려받습니다. 영문/한글 OCR 모델은 패키지에 포함하며 실행 중 이미지를 외부 서비스로 보내지 않습니다.

```powershell
npm test
npx --no-install playwright install chromium
npm run test:desktop
npm run dist:win
```

생성 파일: `release/Baccarat-Live-Analyzer-0.5.7-x64-Portable.zip`. [Windows CI](.github/workflows/windows.yml)는 소스 테스트 → ZIP 빌드 → 압축 해제한 실제 EXE 테스트 후 폴더 전체를 `baccarat-windows-x64-portable`로 제공합니다. 설치 파일·실행 프로토콜 자동 등록은 포함하지 않습니다.

Linux 검증: `bash scripts/test-cloud.sh`. [개발 환경 안내](docs/cloud.md)와 [검증 기록](docs/validation.md)를 참고하세요. 실제 사이트 로그인/제공자 보호 화면은 미검증이며 테스트 자료의 적중률을 실제 예측 성능으로 표현하지 않습니다.

자동 베팅·베팅 클릭/금액 입력·비밀번호 수집·민감한 세션 로그·보안 정책 우회 기능을 구현하지 않습니다. 기존 Chrome 연결 모듈은 개발용 `--enable-chrome-bridge` 실행에만 사용하며 일반 사용에는 필요 없습니다.
