# 월 단위 판매 라이선스 설계안

0.6.0에 인증 서버, 판매자 관리 화면, 구매자 코드 등록·PC 해제, 서버가 고정된 Customer 빌드를 구현했습니다. 운영 서버를 실제 배포한 상태는 아닙니다. 일반 Review 빌드는 기존 관리자 검토용이며 판매용 보호가 없습니다. 판매 전에 HTTPS 서버 운영과 Customer 빌드가 필요합니다. 상세 실행 방법은 [텍스트 설명서](../packaging/license-manual.txt)를 참고하세요.

## 추천 상품과 이용 흐름

- 이용 기간: 1개월부터 12개월까지 1개월 단위로 선택, 등록 PC 1대, 동시 실행 1개.
- 프로그램 파일은 무설치 ZIP으로 배포하고, 첫 실행 때 구매자 코드를 서버에서 활성화합니다.
- 갱신은 같은 고객 라이선스에서 다시 1~12개월을 선택하고, `max(현재 시각, 기존 만료일)`부터 선택한 개월 수만큼 연장합니다. 매월 앱을 새로 배포할 필요가 없습니다.
- 관리자가 결제를 확인하고 발급/연장하는 방식으로 먼저 운영할 수 있습니다. 자동 결제는 별도 단계입니다.
- PC 교체는 관리자 승인으로 이전 등록과 세션을 폐기한 뒤 새 기기를 등록합니다. 초기화 횟수와 변경 기록을 관리합니다.
- 만료·회수 때 새 분석/수집을 제한하며 기존 기록은 삭제하지 않습니다.

## 1~12개월 선택

관리자 발급·연장 화면의 이용 기간 목록은 1개월, 2개월, 3개월, 4개월, 5개월, 6개월, 7개월, 8개월, 9개월, 10개월, 11개월, 12개월입니다. 기본값은 1개월이며 코드마다 선택한 기간을 저장합니다. 구매자가 앱에서 이용 기간을 변경할 수는 없습니다.

기간은 최초 활성화 시점부터 달력 개월 수로 계산합니다. 예를 들어 2026년 10월 15일에 3개월 코드를 처음 인증하면 2027년 1월 15일에 만료됩니다. 한국 시간 기준 같은 날짜·시각을 사용하고, 도착 월에 해당 날짜가 없으면 그 달의 마지막 날로 맞춥니다. 만료 시각은 UTC로 저장하고 서버 시각으로 판정합니다.

서버는 `duration_months`를 1~12의 정수로 검증합니다. 일괄 발급할 때도 기간을 선택하고, CSV와 관리자 검색 결과에 해당 기간을 표시합니다. 발급만 하고 사용하지 않은 코드는 이용 기간이 시작되지 않습니다. 연장 시 선택 기간·이전/변경 만료일·처리 관리자를 이력에 남깁니다.

## 수천 개 코드의 발급과 관리

앱 안에 유효 코드 목록을 넣지 않습니다. 서버가 암호학적으로 안전한 무작위 128비트 이상 코드를 만들고, DB의 고유 제약과 트랜잭션으로 중복 발급과 동시 활성화를 막습니다. 순번이나 날짜를 조합한 예측 가능한 코드는 사용하지 않습니다.

관리자는 1,000개/10,000개 단위로 발급 배치를 만들고 CSV로 내려받을 수 있게 합니다. 원문 코드는 발급 때만 전달하고 DB에는 코드 해시를 저장합니다. 원문 CSV는 구매 활성화 권한이 있는 자료이므로 관리자만 접근합니다. 분실한 미사용 코드는 폐기하고 다시 발급합니다.

각 코드에는 라이선스 ID, 발급 배치, 상품/선택 개월 수(`duration_months`, 1~12), 미사용·사용 중·만료·차단 상태, 최초 등록일, 서버 기준 만료일, 등록 기기, 최근 인증 시각을 연결합니다. 구매자별 검색, 일괄 연장/차단, PC 등록 초기화와 변경 이력을 제공하는 관리자 화면을 둡니다.

수천~수만 건의 코드 목록은 일반 관계형 DB로 충분합니다. 실제 서버 부하는 코드 개수보다 동시 실행 수와 인증 주기가 좌우합니다. 예를 들어 1,000명이 하루 종일 60초마다 인증하면 하루 약 144만 건, 30일 약 4,320만 건의 갱신 요청이 발생합니다. 운영비는 서버·DB·백업·접속 규모에 따라 따로 산정합니다.

## USB/폴더 복사에 대한 제한

기기 등록 때 PC별 Ed25519 키 쌍을 생성합니다. 개인 키는 USB나 앱 폴더에 두지 않고 Windows 사용자 프로필에서 Electron safeStorage/DPAPI로 암호화합니다. 서버에는 공개 키의 해시를 기기 식별값으로 저장합니다. TPM 키는 이번 버전에 구현하지 않았습니다.

활성화와 주기 인증은 새 요청에 대한 기기 키의 서명을 확인합니다. 다른 PC로 앱과 라이선스 파일을 복사해도 등록 기기의 키를 사용할 수 없으므로 인증을 거절합니다. 사용자 이름·IP 주소만으로 PC를 구분하지 않습니다. Windows 재설치나 기기 변경은 등록 초기화 절차로 처리합니다.

서버는 라이선스 1개당 활성 기기 1개와 세션 1개만 허용하고 최대 2분의 사용 권한을 발급합니다. 30초 간격으로 인증을 갱신하며, PC 해제/차단 후 새 등록은 이전 권한 종료까지 최대 2분 대기합니다. 기기와 라이선스에 연결된 권한을 서버 키로 서명하며 Customer 빌드에는 서버 주소와 검증용 공개 키만 고정합니다. 서명용 개인 키와 관리자 권한은 서버에 둡니다. 실행 옵션이나 환경변수로 신뢰 서버를 바꿀 수 없으며 테스트 암호로 판매용 라이선스를 우회할 수 없습니다.

서버 시각으로 만료를 판정하고, 시작할 때 항상 온라인 인증합니다. 앱은 서명된 짧은 권한을 받은 시점의 단조 시계로 유효 시간을 제한합니다. 오프라인 유예는 없습니다. 인증 실패/해제/차단/만료가 확인되면 캡처와 분석 접근을 중지하며 기존 기록을 유지합니다. 일반 종료는 세션만 해제하고 PC 등록은 유지합니다.

## 관리자와 서버 구성

Electron 앱은 인증 API를 사용하고, 별도 HTTPS 프록시 뒤의 Node.js 24 서버와 SQLite가 코드·기기·기간·세션을 관리합니다. 관리자 웹 화면은 서버 초기화 때 정하는 별도 암호와 HttpOnly/SameSite 쿠키로 보호합니다. 같은 출처의 JSON 변경 요청만 허용하고 로그인 제한, 암호 변경, 관리 이력을 포함합니다. 개인 키·관리자 검증값·DB는 고객 배포 파일에 넣지 않습니다. SQLite 단일 프로세스 운영이며 동시 사용자 수천 명의 부하는 별도 검증이 필요합니다.

처음에는 이용 기간 1~12개월 선택 → 결제 확인 → 코드 발급 → PC 활성화 → 선택 기간 사용 → 결제 확인 후 선택 기간만큼 연장 순서가 적합합니다. 인증 서버를 배포하고 비용을 발생시키는 작업은 별도로 진행해야 합니다. 게임 이미지·사이트 로그인 비밀번호·쿠키를 인증 서버로 보낼 필요는 없습니다.

## 보호 범위

이 구조는 일반적인 코드 공유와 USB/폴더 복사를 제한합니다. 사용자가 소유한 PC에서 실행하는 앱의 분석 코드까지 복제를 완전히 막는다고 보장할 수는 없습니다. 코드 서명과 난독화는 보조 수단이며, 만료·기기 등록·세션 결정은 서버에서 관리합니다.
